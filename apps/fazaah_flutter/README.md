# تطبيق فزعة Flutter

تطبيق Flutter للويب وAndroid بواجهة عربية RTL ودخول العميل والمهني ولوحتي تحكم مرتبطتين بخدمة Dart API.

## البناء والتحقق

```bash
flutter pub get
flutter analyze
flutter test
flutter run -d chrome
flutter build web --release
```

ملفات الويب في `build/web`، وتُعرض عبر HTTP لا `file://`.

## تشغيل الواجهات المرتبطة

- دخول البريد يستدعي الخادم ويُنشئ جلسة عند صحة كلمة المرور والدور.
- دخول الهاتف يطلب OTP حقيقيًا؛ لن يعمل في الإنتاج حتى تُهيأ خدمة SMS على الخادم. الرمز لا يظهر إلا إن أعلن الخادم صراحةً أن الاستجابة تطويرية.
- الجلسة تُحفظ باستخدام `flutter_secure_storage`. عند إعادة التشغيل يحاول التطبيق استعادتها عبر API.
- لوحتا العميل والمهني تحمّلان بيانات الحساب والطلبات والتصنيفات والمؤشرات من `/api`. تغيير توفر المهني يُحفظ على الخادم، وتسجيل الخروج يبطل الجلسة.

## عناوين API والأسرار

- Flutter Web يستخدم الأصل نفسه ومسار `/api` افتراضيًا.
- Android أو أصل منفصل يحتاج إلى `--dart-define=FAZAA_API_BASE_URL=https://api.example.com/api` عند البناء/التشغيل.
- يجب ضبط `NEON_DATABASE_URL` كسر وقت التشغيل لخادم Dart عبر مدير أسرار الاستضافة. لا تضف كلمة مرور أو سلسلة اتصال إلى التطبيق أو Git أو `--dart-define`.
- لم تُختبر مصادقة مباشرة على قاعدة الإنتاج لأن سر Neon غير موجود في بيئة العمل؛ الاختبارات تستخدم Backend وهميًا ومخزنًا اختباريًا.

## Android والويب الآمن

- يحتفظ Android بحد `minSdk 23` نفسه للتطبيق الحالي، ويطلب إذن الإنترنت، ويستخدم `flutter_secure_storage 9.2.4` المتوافق مع هذا الحد.
- التخزين الآمن في Flutter Web يستخدم WebCrypto؛ اعرض الموقع عبر HTTPS، ولا تستخدم `file://` أو HTTP عام.
- لم يتوفر Android SDK في بيئة البناء الحالية، لذلك لم يُنشأ APK في هذه المرحلة.

## الحدود الحالية

التسجيل واستعادة كلمة المرور وإنشاء طلب خدمة ورفع الوثائق والإشعارات لم تُنقل بعد. لا تحوّل الإنتاج إلى خادم Dart قبل تهيئة سر Neon، وإعداد SMS، واجتياز اختبار مرحلي ومراجعة أمان مستقلة.
